pivotrl: pivot-weighted reasoning distillation personal research · ongoing 2026

not all tokens in a reasoning trace are equally worth learning from. i detect high-loss pivot points in Kimi K2.5 traces and up-weight them when distilling into Gemma 4.

uniform SFT on reasoning traces dropped GSM8K from 85.5% to 74.5%. pivot-weighted SFT recovered it to 80%. the null result is the point: naive distillation on reasoning traces actively hurts, which isn't obvious from the literature.

rppg with adaptive roi selection masters thesis · sf state · 2025–2026

rPPG reads heart rate from facial video by tracking subtle color changes in skin. most pipelines fix the region to the full face or a static patch, but signal quality shifts across facial regions with motion, lighting, and camera angle.

built oracle, supervised (DAgger), and PPO pipelines to test whether adaptive ROI selection actually helps. oracle hindsight showed strong headroom: the right region exists. the problem is you can't use it live because it requires knowing the future.

rebuilt the task as causal streaming control: each ROI choice updates a running heart-rate estimate, so PPO learns from its own rollouts instead of copying oracle labels. final streaming models reached ~7.37 BPM MAE, beating full-face and supervised baselines under a fixed 3-seed protocol with bootstrap confidence intervals.

failure analysis showed most remaining error comes from side-view drift and ROI-choice mistakes, not model collapse. the gap between oracle and live control is the honest finding.

edge-ai flood alert system bachelors thesis · indian meteorological department · 2024 provisional patent

flood-prone areas in India often don't have reliable internet, so a cloud-dependent alert system is useless to the people who need it most. the whole thing had to run offline.

trained an encoder-decoder LSTM on 45 years of hourly rainfall data (1979–2024) across three Mumbai neighborhoods (Matunga East, Byculla, Dahisar), ~400k records each. MAE around 0.17 across all three. deployed as TFLite on a Raspberry Pi 4 behind a FastAPI backend; a Flutter app uses haversine on GPS to route users to the nearest model. alerts go out over local WLAN, no internet required.
